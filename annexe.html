Section 1

Statique vs Dynamique

📖

Analyse Statique

Lit le texte du code source et en déduit des informations (variables déclarées, structure des branches, conditions composées) sans jamais exécuter le programme. Tout se base sur le PSI (Program Structure Interface), l'arbre syntaxique qu'IntelliJ construit automatiquement pour chaque fichier ouvert.

✅ Couvert par ce document
▶️

Analyse Dynamique

Basée sur l'exécution réelle du programme. JaCoCo, instrumentation du bytecode… Cette partie fait l'objet d'un document séparé.

❌ Non couvert ici
Section 2

Les deux mécanismes d'extension

Un plugin IntelliJ s'accroche à l'IDE de deux façons différentes, déclarées dans plugin.xml.

🔑
Différence clé : une action attend un clic, un extension point réagit à un événement de l'IDE.

2.1 Les actions (<actions>)

Une action est un déclencheur manuel : l'utilisateur doit cliquer (menu, bouton, raccourci clavier) pour qu'elle s'exécute.

Classe de base : com.intellij.openapi.actionSystem.AnAction
Méthode à implémenter : actionPerformed(AnActionEvent e)
Java MonAction.java 
@Override
public void actionPerformed(@NotNull AnActionEvent e) {
    // Code exécuté au clic
}
XML plugin.xml — déclaration action 
<actions>
    <action id="fr.umontpellier.iut.MonAction"
            class="fr.umontpellier.iut.MonAction"
            text="Mon action"
            description="Description affichée en infobulle">
        <add-to-group group-id="EditorPopupMenu" anchor="last"/>
    </action>
</actions>

Groupes disponibles pour add-to-group

group-idEmplacement
EditorPopupMenuClic droit dans le texte de l'éditeur
EditorGutterPopupMenuClic droit dans la marge (numéros de ligne)
ProjectViewPopupMenuClic droit sur un fichier/dossier dans l'arborescence du projet
MainMenuBarre de menu principale (en haut)
ToolsMenuSous-menu Tools existant
ToolbarActionsBarre d'outils (icônes)
💡
Une action peut apparaître dans plusieurs groupes à la fois (plusieurs balises <add-to-group>), et peut avoir un raccourci clavier :
<keyboard-shortcut keymap="$default" first-keystroke="ctrl alt G"/>

2.2 Les extension points (<extensions>)

Un extension point est un mécanisme qu'IntelliJ appelle automatiquement, à un moment précis de son cycle de vie (ouverture de fichier, frappe au clavier, ouverture du projet), sans intervention de l'utilisateur.

localInspection

Tourne en continu pendant que l'utilisateur écrit du code, souligne directement dans l'éditeur. C'est le mécanisme utilisé pour la détection de conditions composées.

Classe : AbstractBaseJavaLocalInspectionTool
XML 
<localInspection
    language="JAVA"
    displayName="Nom affiché dans Settings > Inspections"
    groupName="Catégorie affichée"
    enabledByDefault="true"
    level="WARNING"
    implementationClass="fr.umontpellier.iut.MonInspection"/>
toolWindow

Déclare un panneau latéral persistant. Permet d'afficher un résultat structuré (liste, arbre, graphe) sans bloquer l'utilisateur.

Classe : MyToolWindowFactory
XML 
<toolWindow id="MonToolWindow"
            factoryClass="fr.umontpellier.iut.MyToolWindowFactory"
            anchor="right"/>
postStartupActivity

Code exécuté une fois à l'ouverture du projet. Utile pour un pré-calcul global (ex. scanner tout le projet au démarrage).

XML 
<postStartupActivity implementation="fr.umontpellier.iut.MyStartupActivity"/>
notificationGroup

Pour des alertes non bloquantes (ballon en bas à droite), plus adapté qu'une popup pour un résultat qui arrive après un traitement.

XML 
<notificationGroup id="SAE Notifications" displayType="BALLOON"/>
intentionAction

Les ampoules jaunes 💡 qui proposent une correction rapide dans l'éditeur. Avancé, non prioritaire.

Section 3

Les classes PSI pour parcourir le code

Le PSI est l'arbre syntaxique construit automatiquement par IntelliJ pour chaque fichier source. Toute analyse statique consiste à naviguer dans cet arbre.

PsiFile / PsiJavaFile
PsiClass
PsiMethod
PsiMethod
PsiIfStatement
PsiForStatement
PsiWhileStatement
PsiLocalVariable
PsiExpression
PsiPolyadicExpression
PsiMethodCallExpression

3.1 Classes racines

ClasseRôle
PsiElementInterface de base de tout nœud de l'arbre PSI. Toutes les classes ci-dessous en héritent.
PsiFileReprésente un fichier entier.
PsiJavaFileSpécialisation de PsiFile pour les fichiers .java — donne accès aux classes qu'il contient.

3.2 Structure du code

ClasseRôle
PsiClassUne classe Java. .getMethods() retourne ses méthodes déclarées.
PsiMethodUne méthode. .getName(), .hasModifierProperty("public"), .getBody() pour son contenu.
PsiLocalVariableUne déclaration de variable locale (int x = 5;). .getType(), .getName().
PsiDocCommentOwnerInterface implémentée par tout élément pouvant porter un Javadoc. .getDocComment() renvoie null si absent.

3.3 Structures de contrôle

ClasseRôle
PsiIfStatementUn if (chaque else if imbriqué compte comme un nœud séparé). .getCondition().
PsiWhileStatementUne boucle while.
PsiForStatementUne boucle for classique.
PsiForeachStatementUne boucle for (Type x : collection).
PsiSwitchStatementUn switch.

3.4 Expressions

ClasseRôle
PsiExpression Interface de base de toute expression (une condition, un appel, un calcul).
PsiPolyadicExpression Une expression combinant plusieurs opérandes avec un même opérateur (a && b && c). .getOperationTokenType() (comparer à JavaTokenType.ANDAND / JavaTokenType.OROR, jamais par toString()). .getOperands().
PsiMethodCallExpression Un appel de méthode (obj.methode(args)). .resolveMethod() retrouve la déclaration réelle. .getMethodExpression().getReferenceName() donne le nom brut si la résolution échoue.

3.5 Navigation dans l'arbre — PsiTreeUtil

🗺️
PsiTreeUtil (dans com.intellij.psi.util) est la boîte à outils indispensable pour naviguer dans l'arbre PSI.
MéthodeUsage
getParentOfType(element, Classe.class) Remonte l'arbre depuis un élément jusqu'à trouver un ancêtre du type demandé (ex. retrouver la méthode qui contient la position du curseur).
findChildrenOfType(element, Classe.class) Descend l'arbre depuis un élément et collecte tous les descendants du type demandé (ex. toutes les variables locales d'une méthode).
Section 4

Les classes système (hors PSI)

Ces classes ne représentent pas le code source lui-même, mais le contexte d'exécution du plugin dans l'IDE.

Project

Le projet actuellement ouvert dans l'IDE. Requis par presque toutes les API (popups, ToolWindow...).

Editor

.getCaretModel().getOffset() donne la position du curseur en nombre de caractères depuis le début du fichier.

AnActionEvent

L'événement transmis à actionPerformed(). Point d'entrée pour récupérer le contexte.

CommonDataKeys

Fournit les clés standard pour extraire des données de l'événement : EDITOR, PSI_FILE, PROJECT. Usage : e.getData(CommonDataKeys.EDITOR).

PsiManager

Point d'entrée pour obtenir le PsiFile d'un fichier à partir d'un VirtualFile (utile hors contexte d'une action, ex. dans un postStartupActivity).

Section 5

Où afficher les résultats

Quatre options, du plus simple au plus intégré.

5.1 Popup bloquante — Messages Simple

Simple, bloque l'utilisateur (il doit fermer la popup). Bon pour prototyper vite, pas pour un usage final.

Java 
Messages.showInfoMessage(project, "Contenu", "Titre");
5.2 ToolWindow — panneau persistant ⭐ Recommandé

Déjà en place (MyToolWindowFactory). Permet d'afficher un résultat structuré (liste, arbre, futur graphe) sans bloquer l'utilisateur, et de le garder visible en continu pendant qu'il travaille. C'est l'endroit recommandé pour afficher le graphe de flot de contrôle.

5.3 Soulignement dans l'éditeur — localInspection Automatique

Ne nécessite aucun clic. Le résultat apparaît directement sous le code concerné, avec une infobulle au survol (holder.registerProblem(element, message)). Adapté pour un retour immédiat et localisé.

5.4 Notification non bloquante — NotificationGroup Discret

Ballon discret en bas à droite. Adapté pour un résultat qui arrive après un traitement un peu long, sans interrompre l'utilisateur.

Java 
NotificationGroupManager.getInstance()
    .getNotificationGroup("SAE Notifications")
    .createNotification("Titre", "Contenu", NotificationType.INFORMATION)
    .notify(project);
Section 6

Exemple complet : détection de conditions composées

Cet exemple illustre comment tous les éléments s'articulent ensemble — c'est l'inspection déjà implémentée dans le projet.

💡
Le visiteur (JavaElementVisitor) descend automatiquement tout l'arbre PSI du fichier ; chaque visitXxx() redéfini est appelé par IntelliJ à chaque nœud du type correspondant rencontré, sans que vous ayez à écrire vous-même la boucle de parcours.
Java ComplexConditionInspection.java 
package fr.umontpellier.iut;

import com.intellij.codeInspection.AbstractBaseJavaLocalInspectionTool;
import com.intellij.codeInspection.ProblemsHolder;
import com.intellij.psi.*;
import com.intellij.psi.tree.IElementType;
import org.jetbrains.annotations.NotNull;
import java.util.ArrayList;
import java.util.List;

public class ComplexConditionInspection extends AbstractBaseJavaLocalInspectionTool {

    @Override
    public @NotNull PsiElementVisitor buildVisitor(@NotNull ProblemsHolder holder, boolean isOnTheFly) {
        return new JavaElementVisitor() {
            @Override
            public void visitIfStatement(PsiIfStatement statement) {
                super.visitIfStatement(statement);
                checkCondition(statement.getCondition(), statement, holder);
            }

            @Override
            public void visitWhileStatement(PsiWhileStatement statement) {
                super.visitWhileStatement(statement);
                checkCondition(statement.getCondition(), statement, holder);
            }
        };
    }

    private void checkCondition(PsiExpression condition, PsiElement statement, ProblemsHolder holder) {
        if (condition == null) return;
        if (!(condition instanceof PsiPolyadicExpression)) return;

        PsiPolyadicExpression polyadic = (PsiPolyadicExpression) condition;
        IElementType operator = polyadic.getOperationTokenType();

        boolean isAnd = operator == JavaTokenType.ANDAND;
        boolean isOr  = operator == JavaTokenType.OROR;
        if (!isAnd && !isOr) return;

        String operatorSymbol = isAnd ? "&&" : "||";
        PsiExpression[] operands = polyadic.getOperands();
        if (operands.length < 2) return;

        List<String> conditionTexts = new ArrayList<>();
        for (PsiExpression operand : operands) {
            conditionTexts.add(operand.getText());
        }

        String message = "Condition composée (" + operands.length + " conditions atomiques via "
                + operatorSymbol + ") : " + String.join(" ; ", conditionTexts)
                + " — vérifiez la couverture MC/DC.";

        holder.registerProblem(statement, message);
    }
}
XML plugin.xml — déclaration de l'inspection 
<extensions defaultExtensionNs="com.intellij">
    <localInspection
        language="JAVA"
        displayName="Condition composée (MC/DC)"
        groupName="SAE - Analyse de couverture"
        enabledByDefault="true"
        level="WARNING"
        implementationClass="fr.umontpellier.iut.ComplexConditionInspection"/>
</extensions>
Section 7

Structure générale d'un plugin.xml

XML plugin.xml — structure complète 
<idea-plugin>
    <id>fr.umontpellier.iut.sae</id>
    <name>Nom du plugin</name>
    <vendor>Votre équipe</vendor>

    <!-- Déclare les modules IntelliJ requis -->
    <depends>com.intellij.modules.platform</depends>
    <depends>com.intellij.modules.java</depends>

    <extensions defaultExtensionNs="com.intellij">
        <!-- localInspection, toolWindow, postStartupActivity, notificationGroup ici -->
    </extensions>

    <actions>
        <!-- vos actions ici -->
    </actions>
</idea-plugin>
⚠️
<depends>com.intellij.modules.java</depends> est indispensable dès que vous utilisez une classe PSI spécifique à Java (PsiMethod, PsiIfStatement, etc.) — sans elle, la compilation échoue avec une erreur "cannot find symbol" même si l'import est correct, car ces classes appartiennent au plugin Java, pas au cœur de la plateforme.
