Introduction

À propos de ce tutoriel

Ce tutoriel explique pas à pas comment créer un plugin IntelliJ IDEA : de la création du projet jusqu'à son test dans l'IDE. Il s'adresse à des étudiants qui connaissent déjà Java, mais qui n'ont jamais développé d'extension pour un IDE.

🎯

Objectif

Créer, structurer et lancer un plugin IntelliJ fonctionnel.

📚

Prérequis

Connaissances Java de base. Aucune expérience de plugin nécessaire.

✅

Résultat

Vous saurez où se trouve chaque élément et comment le lancer.

ℹ️
Note sur le module Java : Dans l'écosystème IntelliJ, le langage Java est techniquement considéré comme un plugin (une extension). JetBrains a extrait le moteur Java du noyau de l'IDE dans un module séparé : com.intellij.java.
Étape 1

Créer le projet

Suivez ces étapes pour initialiser votre projet de plugin dans IntelliJ IDEA.

⚠️
Si IDE Plugin n'est pas affiché, allez dans more via plugins…, installez DevKit et relancez l'IDE.
  1. 1

    Ouvrir le dialogue de création

    Ouvrez IntelliJ IDEA et allez dans File → New → Project…

  2. 2

    Sélectionner le type de projet

    Sélectionnez IDE Plugin dans le menu de gauche.

  3. 3

    Nommer le projet

    Donnez un Nom à votre projet et indiquez son emplacement.

  4. 4

    Renseigner Group et Artifact

    Renseignez le Group (ex : com.example) et l'Artifact.

  5. 5

    Choisir le JDK

    Choisissez un JDK compatible (Java 21 ou selon la version ciblée).

  6. 6

    Désactiver le code d'exemple

    Décochez l'option "Add sample code".

  7. 7

    Finaliser

    Cliquez sur Next pour créer le projet.

Concept

L'Artifact

C'est le nom technique de votre projet ou de votre plugin. C'est le nom du fichier final (souvent un fichier .jar ou .zip) qui sera généré et installé dans l'IDE.

Concept

Le Group

Identifie l'organisation, l'entreprise ou l'auteur qui crée le plugin. Il suit généralement la structure inversée d'un nom de domaine internet pour garantir son unicité.

Les fichiers clés

📄 README.md

Généré avec le projet. Ce n'est pas un fichier technique : le plugin fonctionne sans lui. Il rappelle les premières étapes et contient des liens vers la documentation officielle JetBrains.

⚙️ build.gradle.kts

Le fichier le plus important côté build. Déclare les plugins Gradle, la version d'IntelliJ ciblée (bloc intellijPlatform), les dépendances et la version de Java.

⚙️ settings.gradle.kts

Contient le nom du projet Gradle.

⚙️ gradle.properties

Propriétés globales : version du plugin, version de la plateforme, options de la JVM…

🔧 gradlew / gradlew.bat

Le wrapper Gradle. Permet de compiler le projet sans installer Gradle soi-même, avec la bonne version.

☕ src/main/java

C'est ici que vous écrivez le code du plugin (actions, services, inspections, etc.), rangé dans des packages comme n'importe quel projet Java.

🎨 src/main/resources

Contient tout ce qui n'est pas du code Java : plugin.xml, l'icône du plugin, les fichiers de textes (.properties) pour les libellés.

🗝️ META-INF/plugin.xml

La carte d'identité du plugin. L'IDE le lit au démarrage pour savoir ce que votre plugin apporte. Sans lui (ou s'il est mal rempli), le plugin n'est pas chargé.

🧪 src/test

Accueille les tests automatisés du plugin, avec la même organisation en packages que src/main.

Le fichier plugin.xml

C'est la carte d'identité du plugin. L'IDE le lit au démarrage pour savoir ce que votre plugin apporte. Sans lui, le plugin n'est pas chargé.

XML plugin.xml 
<idea-plugin>
    <id>fr.umontpellier.iut.monplugin</id>
    <name>Mon Plugin</name>
    <vendor>Saksouk, Aubert</vendor>
    <description>Description affichée dans la liste des plugins.</description>

    <!-- Dépendance au module Java de l'IDE -->
    <depends>com.intellij.modules.platform</depends>
    <depends>com.intellij.java</depends>

    <actions>
        <!-- Vos actions (menus, raccourcis) sont déclarées ici -->
    </actions>

    <extensions defaultExtensionNs="com.intellij">
        <!-- Vos services, inspections, etc. sont déclarés ici -->
    </extensions>
</idea-plugin>
<id>

Identifiant unique (même logique que le Group vu en partie 1).

<depends>

Les modules dont dépend le plugin. La ligne sur le module Java est indispensable si vous manipulez du code Java.

<actions>

Les boutons, entrées de menu ou raccourcis que l'utilisateur peut déclencher.

<extensions>

Les points d'extension de l'IDE auxquels vous vous branchez (inspections, services, fenêtres d'outils…).

⚠️
Fichiers à ignorer (non versionnés) : Les dossiers build/, .gradle/ et .idea/ sont générés automatiquement. Ajoutez-les à votre .gitignore.
Étape 4

Tester le plugin

Un plugin ne s'exécute pas dans votre IDE de développement : il est lancé dans une seconde instance d'IntelliJ, isolée, appelée sandbox. Vos réglages et projets personnels ne sont donc pas touchés.

💻
IntelliJ de développement
Votre IDE habituel
runIde
🧪
Sandbox IntelliJ
Environnement isolé de test

Lancer le plugin dans l'IDE de test

  1. 1

    Ouvrir l'onglet Gradle

    Ouvrez l'onglet Gradle (à droite de l'IDE).

  2. 2

    Lancer runIde

    Allez dans Tasks → intellij platform → runIde et double-cliquez.

  3. 3

    Tester

    Une nouvelle fenêtre IntelliJ s'ouvre avec votre plugin installé. Ouvrez un projet et testez votre fonctionnalité.

⏱️
Au premier lancement, la sandbox télécharge et prépare l'IDE : cela peut prendre plusieurs minutes.

Déboguer

🐛

Faites un clic droit sur runIde puis choisissez Debug. Les points d'arrêt posés dans votre code sont pris en compte quand vous utilisez le plugin dans la fenêtre de test.

Écrire des tests automatisés

  1. 1

    Placer les tests

    Placez vos tests dans src/test/java.

  2. 2

    Lancer les tests

    Lancez-les avec la tâche Gradle test (Tasks → verification → test) ou avec le bouton vert à côté de la classe de test.

  3. 3

    Tests dépendant de la plateforme

    Pour tester du code qui dépend de la plateforme (fichiers, éditeur, analyse de code), utilisez la classe BasePlatformTestCase en l'ajoutant dans les dépendances de build.gradle.kts.
